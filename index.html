The design philosophy

Minimalist, spacious, semantic.

Semantic HTML should be naturally beautiful, without cluttering tags with utility classes. Generous spacing and fluid typography give it an airy feel; ARIA attributes and role drive every visual state.

1

Attributes say what it is

aria-*, role and data-theme describe an element or its state. Accessibility and aesthetics become the same thing.

2

Classes say how it looks

A curated boutique: layout (.wrapper .stack .cluster .auto-grid) and tone (.positive .negative .warning .accent .muted).

3

Tailwind sits underneath

Tokens are Tailwind tokens. When you need a bespoke exception, the full power of Tailwind v4 is right there.

Two ways to use Blush

Standalone, or the foundation of a Tailwind project.

1. Standalone project.css

Compile once, link the result. No Tailwind in your project, no build step on your side. 

npm install tailwindcss @tailwindcss/cli
npx @tailwindcss/cli -i src/blush.css -o dist/blush.css
<link rel="stylesheet" href="dist/blush.css" />

<main class="wrapper stack">
  <h1>Hello</h1>
  <button>Save</button>
  <button class="outlined negative">Delete</button>
</main>

2. Foundation of a Tailwind project

Import the modules after Tailwind. Blush's tokens become Tailwind utilities that follow the active theme; its own classes are optional. 

@import 'tailwindcss';
@import './blush/src/theme/tokens.css';
/* … theme, base and semantic modules … */
<button class="[--tone:var(--color-valid)]">Approve</button>
<section class="bg-surface-soft border border-border
         rounded-control p-6">
  <h2 class="text-accent">Tailwind on top</h2>
</section>

Tokens and themes

Eight values make a theme.

Four built-in themes, nested anywhere with data-theme. Derived colors (borders, fields, focus rings) are computed from the public tokens, so a small theme is already complete. Use the Theme button, top right, to edit them live.

@layer theme {
  [data-theme='glamour'] {
    --color-accent: oklch(66% 0.21 20);
    --color-surface: oklch(12% 0.04 18);
    --color-text: oklch(98% 0.01 20);
    --color-contrast: oklch(15% 0.04 18);
    --color-invalid: oklch(70% 0.19 25);
    --color-valid: oklch(68% 0.16 145);
    --color-warning: oklch(78% 0.15 75);
    --color-heading: oklch(95% 0.02 20);
    --radius-control: 0.6rem;
    --color-accent-soft: color-mix(
      in oklch,
      oklch(66% 0.21 20) 25%,
      var(--color-surface)
    );
  }
}

The whole API

Small enough for a card.

Class What it does
.positive .negative .warning Tone: the fill on buttons, the text color elsewhere
.accent .muted Filled / neutral button surface; accent or muted text
.outlined Outline shape, combines with any tone
.wrapper .wrapper.wide Centered column with fluid gutters
.stack .cluster .auto-grid Vertical flow, wrapping row, responsive grid
.cover .overlay .overlay-<position> Content over media, ten positions

Styled without classes: text, page layout, media, data, buttons, forms, details, dialog, menu, groups and notices, plus aria-busy, aria-invalid, aria-pressed, aria-expanded, aria-selected and aria-current states. Blush relies on modern CSS: oklch(), color-mix(), cascade layers, nesting and :has().
